# SPOF(Single Point of Failure)란?
- 단일 장애 지점이라는 뜻으로, 그 구성 요소 하나가 멈추면 시스템 전체가 멈추는 지점을 말합니다
- 시스템의 가용성은 가장 약한 고리에 의해 결정되기 때문에 SPOF를 찾아 없애는 것이 고가용성(HA) 설계의 출발점입니다

# SPOF의 예시
- 서버가 1대뿐인 경우 → 서버가 죽으면 서비스 전체가 중단됩니다
- 서버는 여러 대지만 로드 밸런서가 1대인 경우 → 로드 밸런서가 새로운 SPOF가 됩니다
- DB가 1대인 경우 → 애플리케이션 서버를 아무리 늘려도 DB가 죽으면 끝입니다
- 모든 리소스가 하나의 데이터센터(AZ)에 있는 경우 → 정전·네트워크 장애 시 전부 멈춥니다
- 사람이나 프로세스도 SPOF가 될 수 있습니다 (특정 담당자만 배포 방법을 아는 경우 등)

# SPOF를 없애는 방법
## 이중화(Redundancy)
- 같은 역할을 하는 구성 요소를 2개 이상 두는 것입니다
- Active-Active: 모든 노드가 동시에 트래픽을 처리합니다
- Active-Standby: 평소엔 한 대만 동작하고, 장애 시 대기 노드가 역할을 넘겨받습니다 (Failover)

## 스케일 아웃 + 로드 밸런싱
- 서버를 여러 대로 늘리고 로드 밸런서로 트래픽을 분산합니다
- 헬스 체크로 죽은 서버를 자동으로 트래픽 대상에서 제외합니다

## DB 복제(Replication)
- Primary-Replica 구조로 데이터를 복제해 두고, Primary 장애 시 Replica를 승격합니다
- 예: AWS RDS Multi-AZ, Aurora 클러스터

## 지리적 분산
- 여러 AZ나 리전에 리소스를 나눠 배치해 데이터센터 단위 장애에 대비합니다
- DNS(Route53 등)의 헬스 체크·장애 조치 라우팅과 함께 사용합니다

# 주의할 점
- SPOF를 없앤다고 새 구성 요소를 추가하면, 그 구성 요소가 또 다른 SPOF가 될 수 있습니다
- 이중화는 비용과 복잡도를 늘리기 때문에 장애 시 영향도와 비용을 비교해 어디까지 할지 결정해야 합니다
- 실제로 Failover가 동작하는지 주기적으로 테스트해야 의미가 있습니다
