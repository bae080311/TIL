# IAM이란?
- 사용자를 생성하고 그룹에 배치하기 때문에 글로벌 서비스에 해당됩니다.
- **Root account**: 기본적으로 생성되며, 생성 후에는 루트 계정을 더이상 사용해서도, 공유해서도 안됨. 대신 사용자를 생성해야 함
- **Groups**: 그룹에는 사용자만 배치할 수 있음. 다른 그룹은 포함할 수 없음.
- **Users**: 하나의 사용자는 조직 내의 한 사람에 해당됨 필요하다면 사용자들을 그룹으로 묶을 수도 있음

> 사용자와 그룹을 생성하는 이유는 이들이 AWS 계정을 사용하도록 허용하기 위해서입니다

----
## Permissions
사용자 또는 그룹에게 policy, 또는 IAM policy라고 불리는 JSON 문서를 지정할 수 있음 <br>

**ex)**
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": "ec2:Describe*",
            "Resource": "*",
        }, 
      	{
            "Effect": "Allow",
            "Action": "elasticloadbalancing:Describe*",
            "Resource": "*",
        },
      	{
            "Effect": "Allow",
            "Action": [
              "cloudwatch:ListMetrics",
              "cloudwatch:GetMetricStatistics",
              "cloudwatch:Describe*"
            ],
            "Resource": "*",
        },
    ]
}
```
- 이 정책들을 사용해 사용자들의 권한을 정의할 수 있습니다.
- AWS에서는 least privilege principle(최소 권한의 원칙)을 사용
  - 사용자가 꼭 필요로 하는 것 이상의 권한을 주지 않는 것을 의미

## policy 아키텍처
### Consists of
- **Version**: 정책 언어 버전(보통은 "2012-10-17")
- **Id**: 정책을 식별하는 ID (optional)
- **Statement**: 한 개 이상으 ㅣstatements (required)
### Statements consist of
- Sid: Statement ID, Statement의 식별자 (optional)
- Effect: Statement가 특정 API에 접근하는 걸 허용할지 거부할지에 대한 내용 (Allow / Deny)
- Principal: 특정 정책이 적용될 사용자, 계정, 또는 역할
- Action: effect에 기반해 허용 및 거부되는 API 호출의 목록
- Resource: 적용될 action의 리소스 목록
- Condition: Statement가 언제 적용될지 결정 (optional)
### Password Policy
- Strong password = higher security for your account
- AWS에는 다양한 옵션을 이용하여 비밀번호 정책의 생성이 가능
  - 비밀번호 최소 길이 설정
  - 특정 유형의 글자 사용 요구(대문자, 소문자, 숫자, 특수문자 등)
  - IAM 사용자들의 비밀번호 변경을 허용 또는 금지
  - 일정기간이 지난 후 비밀번호 만료, 새 비밀번호 설정 요구
  - 비밀번호 재사용 금지
### Multi Factor Authentication - MFA
- 사용자들은 계정에 접근 권한이 있고, 많은 작업을 할 수 있습니다
- 관리자인 경우 구성을 변경하거나 리소스를 삭제하는 등의 작업을 할 수 있습니다.
- 루트 계정은 무슨 일이 있어도 반드시 보호해야 하고 또한 전체 IAM 사용자들도 보호를 해야합니다
- 비밀번호 이외에 사용할 수 있는 수단으로서 MFA가 있습니다
### MFA devices opitons in AWS
- Virtual MFA device: 하나의 장치에서도 토큰을 여러개 지원합니다. 즉, 루트 계정, IAM 사용자, 또 다른 계정 등 원하는 수 만큼의 계정 및 사용자 등록이 가능합니다
  - Google Authenticator (phone only)
  - Authy (multi-device)
- Universal 2nd Factor (V2F) Security Key: 하나의 보안키에서 여러 루트 계정과 IAM 사용자를 지원합니다
  - Yubikey by Yubico (3rd party)
- Hardware Key fob MFA Device
  - Provided by Gemalto (3rd party)
- Hardware Key Fob MFA Device for AWS GovCloud (US)
  - Proviced by SurepassID (3rd party)
# IAM Role
### IAM Roles for Services
- 몇몇 AWS는 본인 계정에서 실행해야 합니다. 이를 위해서는 사용자와 마찬가지로 어떤 권한이 필요한지에 따라서 AWS 서비스 권한을 부여해야 합니다.
- IAM Role은 Users와 비슷하지만 실제 사람이 사용하도록 만들어진 것이 아니고 AWS 서비스에 의해 사용되도록 만들어짐
- Command roles:
  - EC2 Instance Roles
  - Lambda Function Roles
  - Roles for CloudFormaiton
### IAM Security Tools
- IAM Credientials Report (account-level)
  - 계정에 있는 사용자와 다양한 자격 증명의 상태 포함
- IAM Access Advidsor (user-level)
  - 사용자에게 부여된 서비스의 권한과 해당 서비스에 마지막으로 엑세스한 시간을 볼 수 있습니다.
  - 해당 도구를 사용하여 어떤 권한이 사용되지 않는지 볼 수 있고 이를 통해 사용자의 권한을 줄여 최소 권한의 원칙을 지킬 수 있음
### IAM Guidelines & Best Practices
- 루트 계정은 AWS 계정을 설정할 때를 제외하고 사용X
- One physical user = One AWS user
- 사용자를 그룹에 넣어 해당 그룹에 권한을 부여할 수 있음
- 비밀번호 정책을 강력하게 할 것
- MFA를 사용할 수 있다면 꼭 사용할 것
- AWS 서비스에서 권한을 부여할 때마다 Role을 만들고 사용해야 합니다.
- CLI 혹은 SDK를 사용할 경우 Access Key를 만들고 사용할 것 Access Key는 비밀번호와 같습니다
- 계정의 권한을 감사할 때에는 IAM Credential Report를 사용할 수 있습니다
- Never share IAM users & Access Keys
