# Aurora
- Aurora는 AWS 고유 기술로 오픈 소스는 아닙니다
- Postgres와 MySQL이 호환
- Aurora는 AWS 클라우드 최적화가 되어있으며, RDS의 MySQL에 비해 5배 높은 성능이고 RDS의 Postgres에 비해 3배 높은 성능
- Aurora 스토리지는 자동으로 10GB 단위로 증가하며, 최대 128TB까지 확장할 수 있음
- Aurora는 최대 15개의 복제본을 가질 수 있으며, 복제 지연은 10ms 미만으로 MySQL보다 빠름
- 페일오버는 즉시 이루어지고 가용성이 높음
- 비용은 RDS에 비해 약 20% 정도 높지만 스케일링 측면에서 훨씬 효율적입니다

## Aurora High Availability and Read Scaling
- 3개의 AZ에 걸쳐 데이터 복사본 6개를 저장
    - 쓰기는 6개 중 4개만 성공하면 완료로 처리
    - 읽기는 6개 중 3개만 있으면 가능
- 스토리지는 P2P 복제로 자체 복구(self-healing)됨
- 쓰기는 단일 마스터만 담당하고, 읽기 전용 복제본은 최대 15개
- 마스터 장애 시 30초 내에 자동 페일오버
- 리전 간 복제 지원

## Aurora DB Cluster
- 쓰기 엔드포인트(Writer Endpoint): 항상 마스터를 가리킴. 페일오버가 나도 DNS는 그대로라 앱이 변경 불필요
- 읽기 엔드포인트(Reader Endpoint): 읽기 전용 복제본들에 자동 로드 밸런싱
    - 로드 밸런싱은 **커넥션 단위**로 일어남 (statement 단위가 아님)
- 스토리지는 클러스터 전체가 공유하는 볼륨이고 자동으로 확장됨

## 주요 기능
- 자동 페일오버 / 백업 & 복구
- 보안 및 컴플라이언스 격리
- 버튼 클릭만으로 스케일링
- 다운타임 없는 자동 패치
- 고급 모니터링
- Backtrack: 백업 없이 특정 시점으로 되돌리기

## Aurora Replicas - Auto Scaling
- 읽기 요청이 몰려 복제본 CPU가 튀면, 지표 기반으로 복제본 개수를 자동 조절
- 복제본이 늘어나면 Reader Endpoint가 알아서 새 복제본까지 포함해 분산

## Custom Endpoints
- 특정 인스턴스들만 묶어 별도 엔드포인트를 정의
- 예: 분석 쿼리는 스펙 큰 인스턴스 2대만 묶은 커스텀 엔드포인트로 보냄
- 커스텀 엔드포인트를 쓰기 시작하면 보통 Reader Endpoint는 안 쓰게 됨

## Aurora Serverless
- 실제 사용량에 따라 인스턴스가 자동으로 생성되고 스케일링됨
- 사용량 예측이 어렵거나 간헐적인(intermittent) 워크로드에 적합
- 용량 계획(capacity planning)이 필요 없음
- 초 단위 과금

## Aurora Multi-Master
- 모든 노드가 읽기/쓰기를 모두 수행
- 쓰기에 대한 즉각적인 고가용성이 필요할 때 사용
- 읽기 복제본을 마스터로 승격시키는 방식(기본 Aurora)과는 다름

## Global Aurora
- Cross-Region Read Replicas: 재해 복구에 유용하고 설정이 단순
- Aurora Global Database (권장)
    - 주 리전 1개 (읽기/쓰기)
    - 최대 5개의 읽기 전용 보조 리전, 복제 지연 1초 미만
    - 보조 리전마다 읽기 전용 복제본 최대 16개
    - 리전 승격(재해 복구) RTO 1분 미만

## Aurora Machine Learning
- SQL 쿼리만으로 ML 예측 결과를 받아올 수 있음 (SageMaker 연동)
- Amazon Comprehend 연동으로 감정 분석
- 사용 사례: 부정 거래 탐지, 타겟 광고, 추천

## Aurora Backups
- 자동 백업: 1~35일 보관 (비활성화 불가), 해당 기간 내 특정 시점 복구 가능
- 수동 스냅샷: 사용자가 직접 트리거, 원하는 만큼 보관

## Aurora Database Cloning
- 기존 Aurora 클러스터로부터 새 클러스터를 생성
- 스냅샷 복원보다 훨씬 빠름 — 처음엔 같은 클러스터 볼륨을 공유하고, 변경이 생긴 부분만 갈라짐(copy-on-write)
- 프로덕션에 영향 없이 스테이징 환경을 띄울 때 유용
