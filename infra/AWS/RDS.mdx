# RDS
- 관계형 데이터베이스 서비스의 약자입니다.
- SQL을 쿼리 언어로 사용하는 데이터베이스용 관리형 데이터베이스 서비스입니다.
- AWS에서 관리되는 클라우드 상의 데이터베이스를 생성할 수 있도록 해줍니다
    - Postgres
    - MySQL
    - MariaDB
    - Oracle
    - Microsoft SQL Server
    - Aurora (AWS Proprietary database)
## ECS vs RDS RDS를 쓰는 이유
- RDS는 관리형 서비스이며, AWS는 데이터베이스 뿐만 아니라 다양한 서비스를 제공합니다
    - 프로비저닝, 기본 운영체제 패치 자동화
    - 지속적인 백업과 특정 타임스탬프로 복원
    - 모니터링 대시보드
    - 읽기 성능 향상을 위한 읽기 전용 복제본
    - 재해 복구를 위한 다중 AZ 설정
    - 유지 관리 기간에 업그레이드 가능
    - 수직 및 수평 스케일링 기능
    - EBS로 지원되는 스토리지 (gp2 또는 io1)
- 한가지 단점은 RDS 인스턴스에 SSH로 접속할 수 없음

## Storage Auto Scaling
- 데이터베이스 스토리지가 부족해지고 RDS스토리지 Auto Scaling 기능이 활성화 되어 있으면 RDS가 이를 감지하여 자동으로 스토리지를 확장해줍니다.
- 데이터베이스 스토리지를 수동으로 스케일링하는 작업을 피할 수 있음
- 최대 스토리지 임계값을 설정해야함
- 다음의 경우에 자동으로 스토리지를 수정함
    - 스토리지의 남은 공간이 10% 미만인 경우
    - 스토리지 부족 상태가 5분 이상 지속
    - 마지막 수정 이후 6시간이 지난 경우
- 워크로드를 예측할 수 없는 애플리케이션에 유용
- 모든 RDS DB 엔진 (MariaDB, MySQL, PostgreSQL, SQL Server, Oracle)을 지원

## RDS Read Replicas for read scalability
- 읽기 전용 복제본을 최대 15개까지 생성 가능
- 동일한 가용 영역 또는 가용 영역이나 리전을 걸쳐 생성 가능
- 복제는 비동기 방식으로 진행됩니다. 즉, 읽기 일관적으로 유지됨
- 복제본은 자체 데이터베이스로 승격될 수 있음
- 읽기 전용 복제본을 사용하려는 경우에는 주요 애플리케이션은 모든 연결을 업데이트 해야하며 이를 통해 RDS 클러스터 상의 읽기 전용 복제본 전체 목록을 활용할 수 있음

## Use Cases
- 정상적인 작업 부하를 처리하는 프로덕션 데이터베이스가 있다고 가정하고 데이터를 기반으로 몇가지 보고와 분석을 실시하고자 함 새로운 작업 부하를 처리하기 위해 읽기 전용 복제본을 생성
- 읽기 전용 복제본은 SELECT(=읽기) 명령문에만 사용. (INSERT, UPDATE, DELETE는 제외)
- AWS에서는 데이터가 한 AZ에서 다른 AZ로 이동할 때 네트워크 비용이 발생한다. 하지만, 동일한 리전 내에서의 RDS 읽기 전용 복제본에 대해서는 해당 비용을 지불하지 않는다.

## RDS Multi AZ
- 동기식 복제
- 하나의 DNS 이름 - automatic app failover to stanby
- 가용성 향상
- AZ 손실, 네트워크 손실, 인스턴스 또는 스토리지 장애 발생 시 페일오버 - 스탠바이 데이터베이스가 새로운 마스터가 될 수 있도록 함
- 페일오버는 30초 내에 완료되며, 애플리케이션에 수동으로 조치를 취할 필요가 없음
- 스케일링에는 사용되지 않음
## From Single-AZ to Multi-AZ
- 다운타임이 없는 운영
- 데이터베이스에 대해 수정을 클릭하고 활성화 시키기만 하면 됨
- 내부적으로는 다음이 수행됨
    - 기본 데이터베이스의 RDS가 자동으로 스냅샷 생성
    - 이 스냅샷에서 새로운 DB가 새로운 가용 영역에 복원됨
    - 두개의 데이터베이스 간에 동기화 설정
## RDS Custom
- Oracle & Microsoft SQL Server DatabaseOS: RDS Custom 덕분에 데이터베이스 사용자 지정 기능에 액세스할 수 있음
- RDS: AWS에서의 데이터베이스 설정, 운영 및 확장을 자동화
- Custom: 기저 데이터베이스와 운영 체제에 액세스할 수 있음
    - 내부 설정 구성
    - 패치 설치
    - 네이티브 기능 활성화
    - SSH 또는 SSM 세션 관리자를 통해 RDS 뒤에 있는 기저 EC2 인스턴스에 액세스 가능
- 사용자 지정 설정을 사용하려면 RDS가 수시로 자동화, 유지관리 또는 스케일링과 같은 작업을 수행하지 않도록 자동화를 꺼두는 것이 좋음
- 기저 EC2 인스턴스에 액세스가 가능하므로 문제가 쉽게 발생할 수 있기 때문에 데이터베이스 스냅샷을 만들어두는 것이 권장됨
- RDS vs RDS custom
    - RDS: AWS가 데이터베이스 및 OS 전체를 관리
    - RDS Custom: Oracle과 Microsoft SQL Server에서만 사용 가능, 기저 운영 체제와 데이터베이스에 대한 관리자 권한 전체를 가짐.
## RDS Backups
- 자동 백업
    - 매일 유지 관리 기간에 데이터베이스 전체 백업
    - 트랜잭션 로그는 5분마다 백업 → **5분 전 시점까지 특정 시점 복구(PITR) 가능**
    - 보관 기간 1~35일, 0으로 설정하면 자동 백업 비활성화
- 수동 스냅샷
    - 사용자가 직접 트리거, 원하는 만큼 보관
- 팁: **RDS를 중지(stop)해도 스토리지 비용은 계속 나감**
    - 오래 안 쓸 거면 스냅샷 떠두고 인스턴스를 삭제한 뒤, 필요할 때 스냅샷에서 복원하는 게 저렴

## RDS & Aurora Restore options
- 백업/스냅샷에서 복원하면 **항상 새로운 데이터베이스가 생성됨** (기존 DB에 덮어쓰기 아님)
- S3의 백업으로 MySQL RDS 데이터베이스 복원 (온프레미스 MySQL 백업 → S3 업로드 → 복원)
- S3의 백업으로 Aurora MySQL 클러스터 복원 (Percona XtraBackup으로 백업 → S3 → 복원)

## RDS Security - Encryption
- 저장 데이터 암호화(At-rest)
    - AWS KMS로 마스터 및 복제본을 암호화
    - **암호화는 데이터베이스를 생성(launch)할 때 정의해야 함**
    - 마스터가 암호화되지 않았다면 읽기 전용 복제본도 암호화할 수 없음
    - 암호화되지 않은 DB를 암호화하려면: 스냅샷 → 암호화 옵션으로 복원 → 새 DB로 전환
- 전송 중 암호화(In-flight)
    - 기본적으로 TLS 사용 가능
    - 클라이언트에서 AWS TLS 루트 인증서를 사용해 접속

## RDS Security - 접근 제어
- IAM 인증: 사용자명/비밀번호 대신 IAM 역할로 DB에 접속 가능
- 보안 그룹: 특정 IP나 보안 그룹만 DB 포트로 접근 허용 (네트워크 레벨 제어)
- 감사 로그(Audit Log)를 활성화해 CloudWatch Logs로 장기 보관 가능
- SSH 접속은 불가 (RDS Custom만 예외)
- 정리하면: **권한은 IAM, 네트워크는 보안 그룹, 데이터는 KMS/TLS**

## RDS Proxy
- 완전 관리형 데이터베이스 프록시로 **커넥션 풀링**을 담당
- 앱에서 DB로 열리는 커넥션을 프록시가 모아서 재사용 → DB의 CPU/RAM 부담 감소
- Lambda 같이 인스턴스가 폭발적으로 늘어나는 환경에서 커넥션 고갈("too many connections") 방지
- 서버리스이고 자동 확장, 다중 AZ 구성 가능
- **페일오버 시간을 66% 단축**
- 지원 대상: RDS(MySQL, PostgreSQL, MariaDB, SQL Server), Aurora(MySQL, PostgreSQL)
- **IAM 인증을 강제**할 수 있고, 자격 증명은 AWS Secrets Manager에 저장
- **VPC 내부에서만 접근 가능** — 퍼블릭으로 절대 노출되지 않음

## Database Ports
- 자주 나오는 포트
    - FTP: 21
    - SSH / SFTP: 22
    - HTTP: 80
    - HTTPS: 443
- RDS 데이터베이스 포트
    - PostgreSQL: 5432
    - MySQL: 3306
    - MariaDB: 3306
    - Oracle: 1521
    - MSSQL Server: 1433
    - Aurora: 5432 (PostgreSQL 호환) 또는 3306 (MySQL 호환)
